Open, edit, save

  1. Open the pattern editor. Connect the SD card root, or import a native pattern or editor project JSON.
  2. Choose the exact project, track and letter in the sidebar tree. Expand a track to select a pattern, or use its Add pattern button, including on empty tracks. Missing letters do not fall back to pattern A.
  3. Edit notes and settings. Changes stay in browser memory until saved/exported. Browser recovery is a convenience, not a complete backup.
  4. Use Download project ZIP for an SD-ready project folder, Save changes for the connected card, Export pattern file for a module-ready file, or Export editor project for a workspace backup. The module does not load editor project JSON.

Card writes preserve the previous file as a byte-for-byte .bak and verify the replacement. A backup or write failure stops saving. Keep a separate off-card backup too. Native patterns contain binary trailers: do not edit them as plain JSON. Old poly<letter> sidecars are ignored and never created or migrated.

Work offline and transfer a project later

  1. Create or import a project and edit it without connecting the module.
  2. Click Download project ZIP and choose a project. The ZIP includes its current native patterns, embedded chord/CC data and project/track settings. Unsaved edits are included. With a card connected, unopened patterns from that project are included too.
  3. Extract the ZIP on your computer. Move any existing same-named project folder off the SD card before copying, to avoid merging old pattern files.
  4. Copy the extracted project folder to the card root using your file manager. Wait for copying to finish and safely eject the volume. The module reads the folder, not the ZIP.

A ZIP download does not save to the connected card or mark editor edits as saved. Keep Export editor project JSON to resume your browser workspace later. ZIP exports include native project files, not old sidecars, .bak files, card-root global settings or calibration files. Empty tracks remain empty. CC playback and recording still require the experimental candidate.

Delete patterns and projects

Use the × button beside a pattern or project in the tree. The confirmation names the target and says whether you are deleting from the connected SD card or only the editor workspace. Connected-card deletion happens immediately, without Save changes.

Deleting a pattern removes its native file and .bak backup. Deleting a project removes its whole folder, including all tracks, patterns, settings, backups and other contents. Unsaved edits in the deleted item are discarded. Other items remain intact. Deletion clears undo/redo history and removes deleted items from browser recovery; it cannot be undone. Export a backup first if needed. Clear pattern only empties its notes and automation and keeps the file.

If a card changes during confirmation, deletion stops. An interrupted deletion can be partial: inspect the card before retrying. The tree refreshes and removes confirmed missing items from the workspace. If the result cannot be checked, saving stays disabled until you reopen the card.

Drag velocity bars to set values. Shift-drag adjusts selected notes relatively. Use the inspector for exact values. A whole gesture is one undo step. Out-of-range edits and collisions are rejected rather than silently dropping notes.

Step timing and preview

Patterns have 1–128 steps and up to eight notes per step. Use Step duration beside the step count to choose 1/4, 1/8, 1/16 or 1/32, including triplet variants. This sets the duration of every step in the active pattern, is saved in the native pattern file and controls browser preview speed. Time zoom changes only the view. Tie, slide and ratchet apply to the whole selected step or steps. Notes do not have independent durations. Use zoom and fit controls to navigate. Click the ruler to set an insertion/loop start; Shift-click sets a loop end.

Browser preview is a simple audition instrument, not a complete hardware simulation. Hardware shuffle, generators, modulation, MIDI routing and CV outputs are not reproduced.

CC lanes and external CV

Requires the experimental v0.10.0-alpha.1 firmware. Choose a CC number (for example, 74 for cutoff), then click Add CC lane. The new lane starts empty and becomes the active graph. Click or drag the graph to add points, or use Value at the current step. The Velocity button always stays visible: switch between it and the CC buttons to edit each lane. Adding a CC lane does not remove or change note velocities. Values are quantized to steps. An absent point sends nothing; zero is a real event. Right-click removes a point. Four lanes are available on each melodic track; drums do not use this extension.

Choose MIDI / editor to draw automation or record incoming MIDI CCs. To record external CV, choose input 1–4 as the lane source and set the CC minimum/maximum; reversing the range inverts the mapping. The track/pattern being edited is the destination.

Save the pattern, load it on the candidate firmware, start playback and enable native live recording. MIDI messages follow the configured receive channels; CV is sampled at step boundaries. Disarm to stop recording. Save on the module before leaving the letter, then reopen its pattern file from the SD card in the editor. Recorded controllers appear as CC lane buttons with editable points. If the pattern is already open in the editor, reopen it to read the module’s saved changes. Notes, lane settings and controller points live in the same pattern file.

Candidate status and downgrade limits are documented in CC implementation and hardware acceptance. Do not treat external CV voltage scaling or input order as hardware-verified yet.

Recovery and help

Use the browser draft recovery button after an interrupted session, then export a project backup. If a card file changed externally after opening it, saving stops: reopen the file and reconcile the changes. Get support through this repository’s issue tracker, not the manufacturer.
